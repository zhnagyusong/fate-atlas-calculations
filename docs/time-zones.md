# 为什么历史夏令时会改变排盘输入？

“出生地通常是 UTC+8”不意味着该地所有历史日期都使用同一个偏移。吠陀星历首先需要一个明确的 UTC 时刻；中国历法模块还可能采用单独的真太阳时约定，两者不能互换。

## 可复现的上海样例

```js
import {resolveVedicTime} from '../src/index.js';
resolveVedicTime({date:'1990-08-18',time:'12:00',timeZone:'Asia/Shanghai'});
// utc: 1990-08-18T03:00:00.000Z; offsetMinutes: 540
```

该历史日期的 IANA 规则是 UTC+9。直接手填 UTC+8 会得到04:00Z，差一个小时。如果同时填 Asia/Shanghai 与 UTC+8，本库会拒绝冲突，而不会默默选择一个。这是软件的历史时区解析结果，实际出生钟表是否已经被人为换算仍需调用者确认。

## 两种必须明确处理的时间

- 春季拨快时钟：某些当地钟点不存在。纽约2024-03-10的02:30会被拒绝。
- 秋季拨慢时钟：某些当地钟点出现两次。纽约2024-11-03的01:30必须用实际偏移−4或−5区分，两个时刻相差一小时。

本库使用运行环境的 `Intl.DateTimeFormat` 和 IANA 数据。历史偏移的可用范围和版本依赖运行环境；手动偏移输入也必须准确，不能由坐标猜测。

## 中国历法与吠陀分别输入

| 模块 | 时间约定 |
|---|---|
| 邵子出生输入 `mode:solar` | 已校正真太阳时，不重复校正 |
| 邵子出生输入 `mode:civil` | 手动确认历史偏移，以经度和近似均时差换算 |
| 吠陀 | 当地钟表时间换 UTC，不预先换真太阳时 |

中国四柱的本版日柱使用零点换日，23点晚子时不提前改变日柱；时柱仍按引擎约定处理。不要把“子初换日”和“早晚子时”当成完全相同的规则。
